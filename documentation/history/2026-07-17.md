# 2026-07-17 — Two-phase release workflow

Ported the fixed `release.yml` from `obsidian-remarkable-sync` verbatim (old file was byte-identical to the shared reference). The old workflow built and attested artifacts at the triggering commit, then created the version-bump commit and tag — so the build-provenance attestation was bound to a different commit than the release tag, and the community-catalog review rejected the release ("attestation failed cryptographic verification").

New design: a "prepare" job (dispatch on a branch) bumps versions, generates the changelog, commits, and creates a lightweight tag behind a build gate (`bun run build` + `bun test`, kept — 33 tests pass), then re-dispatches the workflow at the tag ref with `publish=true`. A "publish" job (dispatch-at-tag or bare tag push) builds, attests (no `continue-on-error`), and creates the release, so the attestation cert sha equals the tag commit. Proven live on remarkable-sync 1.5.0.

Repo specifics verified: `release:update-version`, `release:version-bump`, `release:changelog` scripts all exist; `docs/release-notes.md` is generated by `scripts/generate-changelog.ts`, so the workflow's `git add` list needed no change. `scripts/release.sh` summary lines updated to describe the two-phase flow.
