# 2026-07-18 — Community-catalog review fixes (v1.1.1 failed)

The v1.1.1 release (commit 760106a) failed the automated community-catalog checks. Addressed the findings from https://community.obsidian.md/account/plugins/replicate.

## Blocking Error — command id

`src/app/plugin.ts:33` disabled `obsidianmd/commands/no-plugin-id-in-command-id`; the reviewer forbids disabling that rule. The old command id `generate-image-using-replicate` contained the plugin id `replicate`, which triggered the rule.

**Fix (with explicit user approval):** renamed the command id to `generate-images` and removed the eslint-disable. This overrides the previous BR-007 (which had frozen the command id). **Tradeoff accepted by the user:** any user-bound keyboard shortcut on the old id is broken and must be re-bound. BR-007 updated; the command id must not be renamed again.

Updated references: `documentation/Business Rules.md` (BR-007), `documentation/Architecture.md`. Docs/README reference the command _name_ ("Generate image(s) using Replicate.com"), not the id, so no changes needed there.

## Declarative settings API (adopted, with user approval)

`src/app/settingTab/index.ts` — reviewer flagged the tab for not implementing `getSettingDefinitions()` (settings won't appear in Obsidian's settings search on 1.13.0+). User approved the support-window tradeoff:

- Upgraded `obsidian` types `1.12.3` → `1.13.1`; **bumped `manifest.json` `minAppVersion` `0.15.0` → `1.13.0`** (drops support for older Obsidian; `versions.json` gets the `nextVersion → 1.13.0` entry automatically via `scripts/version-bump.ts` at release).
- Rewrote the settings tab declaratively: removed the imperative `display()`; added `getSettingDefinitions()` returning General / Image generation / Support groups. The X-follow button and buy-me-a-coffee badge use `render` definitions.
- Settings are immer-frozen, so the default in-place `setControlValue` would throw — overrode `getControlValue`/`setControlValue` to produce new state via immer and persist through `saveSettings()`. The JSON model-configuration textarea is stored as an object but edited as pretty JSON: `getControlValue` stringifies it, a control `validate` rejects invalid JSON inline (replacing the old `Notice` + debounce path), and `setControlValue` parses it back.
- Obsidian 1.13.1's base `Plugin` now declares `settings?: unknown`, so `ReplicatePlugin.settings` needed the `override` modifier.
