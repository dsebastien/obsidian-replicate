# 2026-10-03: API key moved to Obsidian SecretStorage

## Accomplished

- `apiKey` (plaintext in data.json) replaced by `apiKeySecretName` (default `replicate-api-key`) + `legacySecretMigratedAt`. Key read at use time via `app.secretStorage.getSecret` (`resolveApiKey()`), never cached in settings. Ref: dsebastien/obsidian-cli-rest#13 (secrets in data.json travel with the vault).
- Per-device migration (BR-008): legacy `apiKey` kept in data.json as a read-only bootstrap source; each device copies it into its own secret when absent (on load and on read). First migration never overwrites a different existing secret (suffix `-2`, `-3`, ...). Legacy copy purged after 60 days, via **Remove plain-text copy now**, on rotation to a different value, or by **Clear** (also empties this device's secret: `setSecret(name, '')`, no delete API).
- Settings UI: `SecretComponent` via `Setting.addComponent` in both declarative and `display()` paths, **Clear** button, **Remove plain-text copy now** setting.
- `minAppVersion` 1.8.7 → 1.11.4 (SecretStorage). `versions.json` left to the release script.
- `is-api-key-configured.fn.ts` removed; replaced by `api-key-secret.fn.ts` (pure, tested with `mock-secret-store.ts`). `generateImages` now receives the resolved key.
- Tests: device B bootstrap, idempotency, suffix on conflict, rotation, clear, 60-day purge, button purge, failed setSecret keeps the plaintext.

## Decisions

- Legacy plaintext kept out of `PluginSettings` (private plugin field, written back unchanged on save) so the settings object never caches a key.
- Re-selecting a secret holding the same value as the legacy copy keeps the copy (other devices may still need it); a different value drops it as stale.

- Upgrade path on two synced vaults: both keep generating with no action.
